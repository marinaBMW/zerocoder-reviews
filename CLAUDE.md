# Структура файлов

Для каждой площадки создаётся пара файлов в папке `data/WebReviews/`:
- `reviews-{площадка}.csv` — для чтения в Excel / Google Sheets
- `reviews-{площадка}.json` — для обработки скриптами

**Примеры имён:** `reviews-otzovik.csv`, `reviews-yandex.json`, `reviews-google.csv`, `reviews-2gis.json`

## Поля в каждом файле

| Поле | Описание |
|------|----------|
| `date` | Дата отзыва |
| `name` | Имя студента |
| `rating` | Оценка (число) |
| `title` | Заголовок отзыва |
| `pros` | Достоинства |
| `cons` | Недостатки |
| `url` | Ссылка на отзыв |

Примечание: поля `title`, `pros`, `cons` специфичны для Отзовика. На других площадках, где нет такого разделения, используется одно поле `text`.

**Сортировка:** новые сверху (по убыванию даты).

**Язык:** все отзывы, включая англоязычные.

# Правила нейминга

**Файлы отзывов** — префикс `reviews-`, название площадки строчными латинскими буквами:
- `reviews-otzovik.csv`, `reviews-yandex.csv`, `reviews-2gis.json`

**Датированные снимки** — дата `YYYY-MM-DD` в начале:
- `2026-05-15-reviews-otzovik.csv`

**Скрипты** — описательное имя через дефис:
- `parse-otzovik.py`, `merge-reviews.py`

**Кириллицу в именах файлов не использовать.**

# Правила работы

- Отвечать на отзывы **запрещено**.
- Работать только с файлами внутри папки `zerocoder-reviews/`.
- Отчёты готовить **только по запросу**.
- При нахождении нового источника — сообщение в чате со ссылкой → ждать согласования.

**Google-аккаунт Маришки:** любые действия через её аккаунт (Gmail, Google Drive и др.) — только те, которые она явно подтвердила. Подтверждённое действие: отправка письма-отчёта после запуска `monitor.py`. Всё остальное — спрашивать отдельно.

Сначала показывай план — что и зачем собираешься делать. После согласования — идёшь делать.
